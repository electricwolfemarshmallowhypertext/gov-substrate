# Governance Substrate v0.7.0

2026-10-12

v0.7.0 adds the separate agent deployment and the enforcement work completed after v0.6.0. The v0.6.0 tag, published release and existing DOI records remain unchanged.

## Changes since v0.6.0

- Separate Docker roles for the agent, substrate, effect receiver, audit observer and persistent audit witness. The agent has no network, workspace, provider key or operator credential. Its tools use the substrate's authorization and execution interfaces.
- Separate agent, audit and operator sockets. Agent and audit connections require the expected peer UID through `SO_PEERCRED`. The observer has audit-read-only authority; the witness uses mutual TLS and stores its own chain.
- Protected filesystem patterns apply to reads and writes. Patterns such as `.env*`, `*.key` and `*credentials*` match at any depth and ignore case. In v0.6.0, the protected rule applied only to writes and supported exact paths and directory prefixes.
- A real `send_email` execution adapter, with SMTP delivery checks, one-use grant replay rejection and circuit revocation checks.
- Private-object reads restrict raw network and shared-state egress. The HTTP adapter rejects forbidden private or link-local DNS results before connecting.
- Production agent integration with native model tool calls, UTF-8 completion submission, bounded transport diagnostics, worker environment restrictions and fail-stop stream handling.
- Seven hostile-worker scenarios through the existing deployment, independent effect observations, direct-executor controls and bypass probes from inside the agent container.
- Provider output-assurance handling, an experimental non-publishing release-candidate evaluator and Google Confidential Space attestation integration. Highest-input classification remains the default. These are separate from agent authorization; they do not establish the internals of arbitrary hosted providers.
- Retired AgentLAB pilots and the superseded synthetic authority challenge removed from the source tree and ignored. Active runtime, executor and regression tests remain.

## Evidence locations and scope

The [deployment repair manifest](../evidence/Deployment-Repair-Manifest.json) hashes 14 committed historical receipts using their committed LF bytes. It retains their original fingerprints. The later protected-read, export and seven hostile-worker receipts remain in ignored local `dist/deployed-authority/gov-sub-authority-<run>/` directories and are not included in that manifest.

The source-payload GLM experiment reported `NO ATTACK ATTEMPT`. It supplies no injection-triggered denial and is separate from the enforcement results above. A model declining to make a request does not invalidate a denial observed in another run.

Tool-call batches handle up to 16 entries. Calls after the first are deferred rather than executed before the preceding result is read. Entries beyond 16 are recorded as overflow in the agent result, are not executed and are not submitted to the substrate audit. That audit-coverage limit remains open in this release.

The observer and witness are separate containers on one administrative host. These results do not establish security against a compromised trusted host or kernel. Unit tests with fakes remain regression checks and are not counted as live execution evidence.

Release publication requires all 15 existing CI checks, including the local Qwen and Phi acceptance jobs. Preparing this release makes no paid provider or cloud calls. The paper and its DOI remain separate publication artifacts.
